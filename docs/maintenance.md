# 维护和项目接入

本库维护平台使用知识与最小示例，各项目维护自己的实际命令输入和运行证据。
一个事实只维护在一个地方。新增内容先确定所有者，再写正文及最近一级索引。

## 归属

| 内容 | 位置 |
|---|---|
| 平台命令、输入语义和通用经验 | 对应 docs 主题 |
| 可跨项目复制的少量示例 | examples；保持占位输入 |
| 机构网络、共享账户使用约定 | 对应 institutions 页面 |
| 当前镜像、队列、解释器、任务 YAML、训练参数和结果 | 使用方项目 |
| PID、GPU 利用率、排队中的实时任务状态 | 平台及项目已有运行记录工具 |
| AK/SK、token、密码、个人工具认证 | 系统凭据库或本机私密配置 |

项目接入页注明本库 checkout 的明确路径/托管入口、需要先读的主题，以及项目自己的
资源文档和任务配置位置即可。迁移机器时克隆同一仓库并更新定位信息。
本库不导入项目代码，不建立调度服务、配置继承系统、模板渲染框架或知识副本同步器。

## 核验与更新

版本敏感结论在所在段落注明“何时、哪个工具/环境、用什么检查、证明到哪里”。
官方文档说明、CLI help、生成配置和真实任务结果分别表述，不能用一个“已验证”覆盖全部。
CLI 升级、机构政策变化、实际失败或新使用场景出现时，只核对受影响的主题。

真实使用经验归入现有主题，写清触发条件、可观察症状、直接处理及验证边界，并链接项目的唯一证据。
保存镜像、登记可见、实际拉取和模型执行分别验收；操作成功、资源终态、应用日志和完整 checkpoint 也分别判断。
新证据已扩展范围时直接更新过时概括，保留仍有效的限制，不复制项目的任务清单、实时状态或逐轮日志。
SE3-WAM 的项目入口由研究仓库 `docs/resources/zenith_workflow.md` 维护；
本库只保存跨项目通用步骤，不接管项目调度或恢复契约。

维护顺序：

1. 从索引定位唯一主题，检查当前代码/工具帮助和必要官方资料。
2. 用最小实际操作验证变化；需要云资源时遵循项目自己的资源规则。
3. 改正文及示例，把失效命令直接替换，不保留被推荐的旧/新两条路径。
4. 执行 `python scripts/check.py`，再核对修改过的 YAML/命令。该静态工具的范围见[维护工具](../scripts/INDEX.md)。
5. 形成可复用版本后提交；发布前检查暂存内容不含秘密、本机配置、运行产物或安装器。

需要保存本机文件时先用 `git check-ignore` 确认排除生效。
`.gitignore` 不能清除已经进入 Git 历史的秘密，也不能代替提交前检查。
不把真实凭据移动进库来“验证忽略”。

发行包从已提交版本生成 `git archive --format=zip --prefix=zenith-platform-kb/ --output=<本机包路径> main`，
只包含跟踪文件，不包含 `.git`、未跟踪的 Token、SSH 私钥或 `local_private/`；不要压缩整个工作目录。
根 `.env.example` 必须始终只含占位符；打包前检查跟踪清单，不能假定 Git 历史中已有的秘密会被排除。
私有仓库用户须有读取权限；ZIP 可供获准接收知识库的用户离线读取，接入平台仍需其本人网络与凭据。

默认活跃文档、示例与工具控制在 25 个文件、1 MiB 内，根入口约一屏。
2026-10 Zenith 增加一个可执行入口、HTTP 工具及测试、两份 JSON 示例；继续复用主题，避免再复制一套平台说明。
这些约束用于发现重复，不是删掉必要前提的理由。确需扩大职责时先说明用途与使用方。
不新增平行的待验证总表、逐轮审计记录、发布回执或复杂状态门。

## 重构来源及边界

原始资料为用户提供的 `火山云机器学习平台开发指南0919.zip`，正文主要更新于 2026 年 6—7 月。
2026-09-19 重构时：00–06 与 13 的有效平台步骤归入相应主题；07/08 的不确定项和实操
步骤归回正文；10/11/12 的通用失败经验归入排障和镜像页；14 归为机构说明。
09/11-TOS/15/16 的账户、项目和资产状态不作为本库默认事实。

原 research 七份报告的有用出处融入主题；不整篇携带重复调研。
原 templates 中的旧项目训练、镜像验收、代理、同步和环境安装程序不进入通用库。
被复用的思想重写为最小示例，其原脚本不被标为本库支持的执行入口。

原 ZIP 内的 Office 原件、VPN 安装器、工具二进制和凭据材料未纳入本库。
原 ZIP 仍是用户本机历史来源，含私密材料，不作为共享发行包；本轮未删除原包或修改凭据。
Office 文档的全部正文和截图未逐项复核，因此本库不声称完整保留其中每条机构细则。
需要细则时由维护者定向审阅并更新机构页。

本轮具体证据：远端 Linux `volc/1.2.55` 的 version 与任务相关 help、实际
`ml_task template --example=false` 输出，及 `tosutil v4.1.7` 的 version/cp/config help。
版本与字段结论分别保存在 [CLI](cli.md)、[任务](custom-tasks.md)、[存储](storage.md)页。
未运行本库模板的云端任务，未对所有机构权限和历史镜像做重新验收。
