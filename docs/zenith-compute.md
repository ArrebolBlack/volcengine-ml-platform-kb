# Zenith 开发机、连接与训练

入口和证据范围见 [Zenith](zenith.md)。2026-09-22 以普通用户浏览创建表单并核对帮助；
没有提交资源，也没有执行启停、SSH、训练或 DDP。下文区分表单实见与帮助声明。

## 开发机：创建到运行

进入 [我的开发机](http://10.1.130.101/my/instances)，点击“创建开发机”。
2026-09-22 实见表单字段如下；选择仅修改未提交表单。

| 字段 | 当前用法 |
|---|---|
| 名称 | 可留空，自动生成 `dev-MMDD-HHMM`；帮助规定 4–32 位小写字母、数字、中划线，字母开头、字母/数字结尾 |
| 型号、卡数 | 先型号后单机卡数；规格由组织分配，CPU/内存显示参考范围；不是直接选择原生 Flavor |
| 镜像 | 标准镜像按最终资源区映射，也可搜索目录；选区专属镜像会约束落点 |
| 资源区 | 可指定已开放且符合当前规格的资源区，或自动分配；GPU 卡型目录不表示空闲库存 |
| 项目 | 开发机可不选；选项目改变卡时归集和授权存储，不能转移个人所有权 |
| 优先级 | 默认“一般”，可中断工作才选“低优”；表单写明低优仅资源区 5 可用 |
| 存储 | 当前显示个人、项目、公共三个开关及预览；由规则自动配置，普通用户开关禁用，手动调整由总管理员操作 |
| SSH | 自动配置；区 5 公网 SSH、区 6 安全中继、区 1–4 厂商端点；仍需个人公钥授权 |

2026-09-22 实见 A100 开发机可选区 4、5；区 10 目录标示 NVIDIA RTX PRO 6000 96GB，
在 A100 规格下不可选。区 1、2、3、6 当时无开放卡型。目录随组织配置变化，不能当成长期容量表。
选择区 5 后显示 `/personal_fast_storage` 与 `/public_fast_storage` 自动挂载预览；
自动分配的初始方案反而提示未提供这两类存储。需要这些目录时，明确选择支持它们的区并核对预览。

2026-09-26 个人 API 文档新增开发机 `storage_mode`；是否保留个人存储会约束调度区，
天翼网页模式要求显式接受无个人存储。参数细节见[创建契约](zenith-account-admin.md)，
不要将 9 月 22 日的表单预览当成新版 API 的默认挂载保证。

镜像支持仓库名、版本片段、`仓库名:版本` 或完整带 Tag 地址搜索；宽泛搜索结果有限。
标签一次一个、再次点击取消；标签继续筛选搜索结果，关闭下拉后搜索词清空，标签可保留。
筛选不自动替换已选镜像；长名称展开后核对。默认镜像是运行环境，不保证有项目依赖。

容量窗口约 15 秒刷新，样本最多缓存 60 秒，超过 90 秒过期。余量未知不等于零；
多资源池无法确认落点时可能显示未知。快照不预留容量，也不提供队列位置或预计等待时间。
“一键创建”成功只表示请求接受；等待记录出现、状态运行中，再检查连接。
提交后不要因列表暂空而重复创建；帮助说明约 5/35 秒补拉，云端通常约 30 秒或更久同步。
日常列表可见时约 15 秒更新，离开标签页暂停，返回补拉。

来源：[工作台](http://10.1.130.101/help/compute/workbench.html)、
[快速开始](http://10.1.130.101/help/guide/quick-start.html)。旧快速开始仍提到手动公网开关、
勾选目录；当前自动配置表单优先。

## 详情、生命周期和监控

点击开发机行进入带 ID 的独立详情地址，查看状态、规格、系统盘持久性、挂载、连接和停止原因。
标识/网络/计费、状态日志、监控、项目归属通常按需展开。操作使用**厂商实例 ID**，不能用
Zenith 内部台账号代替。地址可复制但不会增加接收者权限。

| 操作 | 使用与验收 |
|---|---|
| 启动 | 已停止/搁置的原实例恢复；仍在原池/队列/可用区，不迁移寻找容量。最终以运行中为准 |
| 停止 | 先保存输出；提交后等已停止。系统盘、网络等附属费用未必归零 |
| 重启 | 原实例重启，连接中断；不创建替代机；区 1–4 非持久系统盘可能清空 |
| 删除 | 备份后删除；请求接受不等于已释放。系统盘数据通常不可恢复 |
| 调整卡数 | 当前厂商明确支持时同型号变配；主要火山 MLP。A100/NVIDIA A100 80GB 可视同型，H100 不可改成 A100 |
| 扩容系统盘 | 火山 MLP **仅总管理员**，只能增大；核对实时盘量和队列云盘配额，随后核对系统内分区 |
| 重建/更新实例 | 高级权限且厂商支持；重建替换系统环境。完整挂载/端口列表会覆盖旧配置，空挂载列表表示清空 |

列表“陈旧”仅表示近期未确认，不能据此当作已删除。请求失败/超时后先刷新详情，不根据前端旧状态重发。
“命令任务运行中”也不是开发机已开机。停止原因未知时不得推断为额度耗尽。

状态日志记录生命周期、公钥注入、开停计费及额度拒绝，**不是应用 stdout**。
可见且跟随时非终态状态日志约 10 秒刷新；停止后补读最终历史及稍后的计费记录。
监控是厂商/平台按需快照，缺少指标不等于零负载。实际科研日志保存到持久目录。

管理员实例管理还支持厂商、状态、队列、有 SSH、名称/ID/GPU 型号筛选，以及“平台管理/可监控”范围。
专业创建四步：厂商 → 地域/可用区/规格/队列 → 名称/项目/镜像/计费/盘/RDMA/SSH/挂载 → 核对并提交。
这些原生字段不是普通用户工作台入口。已有项目改绑另一项目需管理员。

来源：[实例管理](http://10.1.130.101/help/compute/instances.html)。

## SSH 与网页终端

在 [SSH 密钥](http://10.1.130.101/ssh-keys) 导入 OpenSSH **单行公钥**，支持 Ed25519、RSA、ECDSA，
每人最多 10 把。名称可识别设备；不要把私钥放入公钥框。平台生成 Ed25519 时私钥只显示一次，
关闭后无法恢复。本次只阅读入口，没有导入、生成或变更密钥。

“默认”只是管理标记；自动补注入读取当前登记的全部公钥。新机可连接后尝试注入；新增公钥不会
立即写入所有旧机，旧机用详情“补注入公钥”。通过 Zenith 启动原实例会重新排队注入所有者公钥；
直接厂商启动或独立重启仍需检查。删除平台密钥记录不会移除实例 `authorized_keys` 中已写入的公钥。

连接步骤：运行中 → 详情/连接详情 → 确认厂商实例 ID → 获取 SSH 信息 → 核对用户名、主机、端口、
端点类型 → 用对应私钥连接 → 确认远端主机/目录。不要猜用户名/端口。平台端点变更后重新获取。
实例刚运行时 SSH 服务和注入可能尚未完成；先看“我的公钥”的状态、次数、新增/跳过及错误。

| 端点/厂商 | 操作区别 |
|---|---|
| 公网直连 | 使用页面生成命令及已授权私钥 |
| 仅内网 | 本机需可达专网/VPN/跳板；网页终端另取决于平台部署到端点的网络，平台不可达时禁用；本机不可达不等于平台不可达 |
| Zenith 中转 · 稳定端口 | 无问常见；复制页面命令，内部封装跳板/AICoder，仍由实例公钥认证；重启通常保留端口 |
| 天翼 BC | 主账号未预置平台终端公钥时可能只开放 JupyterLab；通过 Jupyter 补写公钥不等于开启厂商 SSH 端口 |
| 无问应用链接 | Code Server/JupyterLab/TensorBoard 要先在机内启动并配置厂商监听端口；占位链接不是服务健康证明 |

网页终端需操作权限、实例所有权、厂商 ID、允许队列、可达 SSH、平台终端公钥。
等待“已连接”后使用；重新连接是新会话，不能恢复旧 shell 屏幕和交互状态。
长任务使用训练任务或镜像中已有的 tmux 等工具，并持续写 checkpoint；浏览器标签页不是保活机制。
可用应用链接可能要求厂商独立登录。

来源：[连接实例](http://10.1.130.101/help/compute/connection.html)、
[SSH 密钥](http://10.1.130.101/help/account/ssh-keys.html)。程序化 SSH 入口见
[个人 API/CLI](zenith-account-admin.md)。

## 训练：创建、DDP、观察与重试

进入 [我的任务](http://10.1.130.101/my/jobs) →“新建训练任务”。
2026-09-22 实见普通用户表单如下，**没有 Dry-run 开关**：

| 字段 | 用法 |
|---|---|
| 任务名、入口命令 | 必填；命令自己处理 `cd`、解释器、参数，不能仅选择框架就假定代码自动分布式 |
| 调度类型 | “标准任务”默认选中；“低优任务”可能被厂商抢占 |
| 型号、卡数 | A100、PRO6000 当时可见；A100 单节点 1/2/4/8 卡选项 |
| 资源区 | 自动或指定；与镜像、规格、实际存储及任务路由相容 |
| Worker 数 | 默认 1；**总 GPU = 每 Worker 卡数 × Worker 数**，如 8×2＝16 GPU |
| 镜像 | 随规格加载具体镜像；A100 单卡当时默认 `pytorch:2.9.1-cu12.9.1-py3.11-ubuntu22.04（标准） · 资源区5`，非持久承诺 |
| 框架 | 实见 Custom、PyTorch DDP、TensorFlow、MPI、Ray；改变训练模式，不替换镜像 |
| 项目 | 普通用户和项目管理员当前必选有效项目；无项目低优是后续制度，不能直接套用 |
| 环境变量 | “添加”逐项填写；不覆盖平台注入的 `MLP_*` |
| 最长运行时间 | 单位秒，留空平台默认；到上限会停，要给准备/保存输出留时间 |
| 描述 | 可选，记录目的与配置说明 |

本次选择 A100/1 卡/区 5/有效项目后，表单仍未展示帮助描述的个人/项目/公共存储开关。
因此不能把开发机的挂载预览自动当成任务挂载。个人 Token 的准入入口是
`POST /pt/api/compute-offerings/{id}/admission`（需 `catalog:read`，见[API与CLI](zenith-account-admin.md)）；
它只检查准入，挂载仍属 `unchecked`，不能解决这里的路径缺口。规格接口的存储预览与授权盘目录
也不等于任务实际挂载清单；个人任务列表/详情契约不提供该清单。正式运行前须由当前配置/管理员确认
任务自动挂载，再在已授权的短任务中验证读写；缺少证据时不要提交依赖这些目录的长任务，
也不要把同名普通目录当持久卷。
镜像加载前曾短暂显示 `__standard__`；等待具体目录加载，不能将它当成镜像 URL。

选择 PyTorch DDP 后实见并点选“填入 DDP 启动模板”，入口命令填为下式；未提交。
每个 Worker 执行相同命令，替换 `train.py` 并使用正确工作目录：

```bash
torchrun \
  --nnodes="${MLP_WORKER_NUM:?}" \
  --nproc-per-node="${MLP_WORKER_GPU:?}" \
  --node-rank="${MLP_ROLE_INDEX:?}" \
  --master-addr="${MLP_WORKER_0_HOST:?}" \
  --master-port="${MLP_WORKER_0_PORT:?}" \
  train.py
```

MLP 提供节点信息；`torchrun` 设置 `RANK/LOCAL_RANK/WORLD_SIZE`。代码需支持 DDP，通常按
`LOCAL_RANK` 绑 GPU 并使用 `env://`。不要为所有 Worker 写死相同 node rank/master，或把环境缺失
静默改成单机训练。缺必需变量即失败是模板的预期。同构 DDP 不加 `ps` 角色。

准备镜像依赖 → 小规模验证命令和持久输出 → 核对总 GPU、项目/个人额度、镜像与挂载 → 创建。
帮助声明若提交提示“准备/结果待确认”，保留锁定配置并用“重试同一操作”，避免改名重复创建。
“复制并重新配置”创建独立新任务，不改原任务；核对带入镜像、规格、Worker、项目、存储、命令和
环境变量。旧任务缺真实配置时需补填，失效挂载不能静默丢弃；他人项目任务可见不等于可复制原始配置。

普通任务页按状态过滤、分页、刷新，按 Zenith 记录的创建者/项目与厂商任务 ID 确定范围，不按名称认领。
详情看状态/退出原因、角色/副本、运行实例、监控快照、实时日志、事件/TensorBoard 能力及厂商入口。
“云端账号”或“未记录提交人”不能据此识别具体人。

任务列表主要手动刷新，不会持续追踪所有任务。支持的实时日志在可见时约 2.5 秒更新、默认跟随最新；
上滚暂停，“查看最新”恢复；切任务/Worker 回到最新。近期日志有行数上限，不是完整归档。
区 5 新任务使用 Zenith 日志中继，旧任务可能无中继；能力标签不表示内嵌事件或 TensorBoard 已运行。
已完成仍要验收输出/指标；失败看退出码、事件和真实程序日志；停止中断未保存进度；删除终态记录前
保存诊断资料，任务删除不等于删除底层存储文件。

个人 API 2.0.1 没有原生训练日志、事件或 TensorBoard 查询端点。命令行自动化可由训练入口将
stdout/stderr、退出结果和产物写入已验证的持久目录，再由挂同一卷的本人开发机取回；
这是待实测的工作负载方案，不是平台日志 API，也不能在任务未启动时提供调度错误日志。
任务 ID 不能作为开发机 ID 用于 SSH；非交互连接方法见[API/CLI](zenith-account-admin.md)。

运维原生创建才可配队列、Flavor、可用区、异构多角色、原生挂载和 Dry-run。MLP 支持异构 Role；
无问仅同构 Worker；帮助称天翼训练创建需 IAM 授权暂未开放。Dry-run 只验参数，不预留资源。
任务控制可因厂商能力提供名称/描述、优先级、最大运行/保留时间、资源预约；提交后查详情确认生效。
区 5 包含 MLP3/MLP4，不同池余卡不能拼为单一大规格。

来源：[训练任务](http://10.1.130.101/help/workloads/training.html)。

## 三种回收机制必须分清

| 机制 | 触发与保障 |
|---|---|
| 开发机空闲回收 | 帮助称默认关闭、空闲提醒默认开启；管理员启用后，有效监控证明本轮运行满 2 小时、GPU 利用率上限≤10%、近期无活动，才至少提前 15 分钟站内预告 |
| 低优开发机让出队列 | 同队列一般任务排队且空闲不足；即使在训练也可回收，至少提前 15 分钟站内预告，届时再核对需求 |
| 火山低优训练任务 | 厂商原生抢占，**不保证 15 分钟预告**；平台不代保存 checkpoint、不承诺自动续跑 |

空闲机制保护条件：最近 15 分钟有 GPU 利用率/GPU 进程/显存>256 MiB/CPU>10%，或监控不足、
最新有效数据超过 90 秒、运行开始时间不明、活动字段不全，均继续观察。管理员开发机不参与自动回收；
平台训练任务不参加开发机空闲回收。开发机中 `SSH/nohup` 启动的训练仍随开发机管理。
预告宽限从通知生成算起，不从阅读算；活动恢复/需求消失/容量恢复/身份变化可取消，旧通知不证明已经关机。
故障及厂商原生抢占不享有平台预告保证。空闲提醒本身不安排关机。
新学生整节点预留制度另有无宽限回收目标，见[账户与政策](zenith-account-admin.md)，不要套入现有开发机规则。

上述精确阈值为[实例管理帮助](http://10.1.130.101/help/compute/instances.html)记载，
本轮未触发回收验证；当前是否启用由管理员配置决定。

## 推理服务（帮助记载，当前账号无入口）

仅运维管理员开放。服务是流量入口，部署是其下的镜像/命令/资源副本；一个服务可有多个部署。
创建：选择厂商 → 已有服务或新建服务名称/描述 → 部署名称、镜像 URL、命令、队列、规格 ID、
可用区、副本 1–16、可选优先级 1–9/描述/模型 → 校验与提交。
关联模型仅提示最新版本存储路径，不复制、挂载、改命令或验证权限。
新建服务的 Dry-run 完成服务参数校验后跳过实际部署创建；通过不保证库存。
验收要达到期望可用副本并通过真实业务探测，“服务中”不足以证明健康。
停止服务影响全部部署/流量，停止部署仅影响该版本；停止后确认副本释放，删除前处理调用方和数据。
列表/详情主要手动刷新，不承诺自动无损流量切换。

来源：[推理服务](http://10.1.130.101/help/workloads/inference.html)。
