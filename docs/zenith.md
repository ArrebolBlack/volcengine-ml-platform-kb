# Zenith 平台入口与 Agent 快速开始

Zenith 是 `10.1.130.101` 上的多云算力集成平台。当前帮助简介列出火山 MLP、天翼 BC、无问和
阿里云；实例、厂商和个人 API 页面同时保留资源区 10 的百度百舸能力说明。厂商目录存在这项
文档差异，执行时以实时 `capabilities` 和页面实际选项为准。
它有自己的账号、资源所有权、配额、目录和个人 API；本库原有 `volc`/veMLP 文档不能直接替代它。
从 Zenith 创建的资源按 Zenith 工作流操作；公网火山控制台或 `volc` 创建的旧资源不自动归入“我的”。

## 从哪里进入

- [控制台：我的总览](http://10.1.130.101/my)
- [帮助中心](http://10.1.130.101/help/)：支持搜索按钮或 `Ctrl+K`，按专题定位。
- [计算与连接](zenith-compute.md)：开发机、SSH、训练、DDP、回收、推理。
- [数据与资产](zenith-data.md)：镜像、模型、持久存储、文件与迁移。
- [账户、API 与管理](zenith-account-admin.md)：权限、项目、卡时、Token/CLI、管理员功能。
- 本页“证据范围与仍缺的操作经验”段落记录 2026-10-03 的帮助中心逐页更新时间、新增/失效路由和版本冲突。

其他 Agent 从 [平台文档索引](INDEX.md)进入，只读本次需要的主题；本机 checkout 位置由接入项目
资源文档记录。实际实验镜像、配置、任务 ID、结果归使用方项目，不复制到本库。

## CLI 与 Codex 能做到什么

**当前不能仅靠官方 `zenith` CLI 完整操作平台，也不能声称已实现全平台无网页操作。**
个人 HTTP API 可补齐开发机和训练创建；系统 SSH 可用于本人开发机内的命令、代码和文件。
这条组合路径具备常规研究自动化的接口基础；2026-10-03 已用现有个人 Token 完成只读 API 与本地 GPU Fleet 仪表盘闭环，写入和调度仍未实测。
实例删除、事件/TensorBoard、产物下载和资产管理等仍缺完整公开的个人 API 闭环；当前训练日志/副本诊断
已有 HTTP 读取路径，已用现有 Token 做只读验收。完整覆盖表、接入前提和
非交互 SSH 方法见[账户与 API](zenith-account-admin.md)。Zenith 资源管理不能套用原生 `volc` 命令或 AK/SK；
机内访问已独立授权的 TOS、vePFS 和镜像另按[现有火山资产复用路径](zenith-data.md#复用已有火山数据与镜像)执行。

Agent 接入平台 API 时，依次确认：实际受支持的 HTTPS origin 和 Token → 查询本人身份、
项目、额度、规格/镜像及当前 schema → 按任务选择 API 或官方 CLI → 在已授权的本人资源上验证
SSH、挂载和输出。官方 CLI 另需可信 Release 包和受支持的运行环境；HTTP API 不依赖安装 CLI。
2026-10-03 本机检查仍能找到 Node.js 24 和 OpenSSH，但找不到 `zenith` 命令；已用现有 Token 验证 capabilities、本人资源列表、详情、日志和副本等只读 API。
已有开发机可先从登录后的控制台取得端点，复用已注入的公钥和本机私钥走系统 SSH，
不必等待 API Token 或官方 CLI；2026-09-27 已完成这一条[非交互连接路径](zenith-account-admin.md#codex-的非交互-ssh-路径)。

线上新增的 CLI 专题把自动化边界写得更清楚：CLI 预览要求 Node.js 24/npm 11，当前只验证
macOS/Linux；从有权限的 `cli-v<版本>` Release 同时取得 CLI、Skills、清单、安装说明和
SHA-256 文件，Skills 安装到项目 `.agents/skills/zenith` 或个人 `~/.agents/skills/zenith`。
它已覆盖只读查询、实例启停/重启/改配、SSH、操作回执恢复、准入预检、训练取消以及对象源/对象
签名和 STS；实例创建、训练创建/列表/详情/日志、副本诊断、平台 ID 别名、手动挂载和管理员功能
仍未实现或不属于个人 CLI。Windows 凭据/恢复存储尚未验证，不能把 CLI 当成全平台完全 CLI。

## 控制台最短启动路径

1. 在能够打开上述内网地址的浏览器中访问控制台，核对右上角账号和身份。2026-09-27 用户确认使用
   钉钉扫码，Agent 已复用 Chrome 登录会话；扫码由用户完成。Chrome 与 Codex 内置浏览器会话独立，
   内置页停在登录页不能据此要求已登录的用户重新扫码。当前登录会话只保存在站点 Cookie，平台帮助
   声称不会将密码、Token 或私钥写入 local/session storage；退出应使用用户菜单，关闭标签页不等于服务端退出。
   具体 VPN 或校外接入方案仍未确认。
2. 打开“组织与项目”，确认组织分配的规格和存储开关、有效项目关系；打开“我的总览”看当前
   周期、剩余额度和资源区创建能力。组织和项目是独立关系，组织成员不自动获得项目目录。
3. 在“SSH 密钥”登记自己设备的公钥；已有密钥先核对，不重复生成或扩大访问。具体步骤见计算页。
4. 交互调试：我的开发机 → 创建开发机 → 型号/单机卡数 → 镜像/资源区 → 可选项目 → 一般优先级
   → 核对自动存储路径。需要个人高速目录时选择明确支持的区，不仅凭“自动分配”推断会挂载。
5. 提交后先等记录出现、运行中、连接信息/公钥就绪；复制页面 SSH 命令或打开可用终端/应用。
   检查真实挂载后，才把代码、环境、数据和输出放入持久目录。
6. 批量训练：先在目标环境验证入口，再“我的任务 → 新建训练任务”，选择标准任务、镜像、
   每 Worker 卡数、Worker 数及有效项目；核对总 GPU、挂载和 checkpoint。分布式模板见计算页。
7. 观察状态与真实日志，完成后验证输出可读取，再按任务授权停止/释放。网页成功提示只证明请求接受。

在已授权的 Linux 开发机上可做以下最小环境检查；9 月 27 日已通过 SSH 执行主机身份、GPU 可见性、
有界 PFS/HDF5 读写和挂载检查。下面的通用 `pwd`、PyTorch/CUDA 检查块尚未整体重跑：

```bash
hostname
pwd
nvidia-smi
findmnt -T /personal_fast_storage
df -hT /personal_fast_storage
python -c 'import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.device_count())'
python -c 'import torch; x=torch.arange(1024, device="cuda"); print((x*x).sum().item())'
```

上述挂载命令按本次页面实际路径替换；确认 `findmnt` 返回的来源与预期持久卷一致，不能仅看目录存在。
最后一条只验证很小的真实 GPU 运算，不代表训练或多卡性能验收。项目目录使用页面实际路径，
不要复制他人的登录名、工号或原生 vePFS 子路径。大任务前按实际工作负载检查所需模块及少量输出读写。

## 先诊断再重试

|---|---|
| 无入口/按钮禁用 | 平台角色、产品身份、项目关系、本人所有权、厂商能力；不要仅凭按钮存在认定授权 |
| 资源区有卡但创建失败 | 单机碎片、落点池、规格、总提交/运行配额、卡时、镜像/存储约束；快照不预留 |
| 请求超时或列表未出现 | 先刷新与查询原操作；不要改名重复创建，也不要自动切区创建第二份 |
| 有目录但文件消失/不互通 | 实际挂载来源、资源区、池和个人卷；同路径不同区不是同一数据 |
| 无承载开发机 | 检查平台承载服务或自己运行机是否真实挂载且可达；重新检测；对象桶不需个人开发机 |
| SSH 失败 | 运行态、厂商 ID、端点可达、公钥注入、对应私钥；内网地址不能当公网用 |
| “已完成”但无结果 | 真实程序退出/日志、输出路径、文件可读与指标；完成状态不代表科学验收 |
| 余额低/查询失败 | 先看包内/按量/未知徽标；包内不耗现金，接口失败不等于余额零 |

需要反馈时带页面、操作时间、资源名称和厂商 ID、身份/项目、期望、完整脱敏错误；
从右上角“提交反馈”提交后可在“我的反馈”跟踪。不得附密码、私钥、Token 或临时签名 URL。
