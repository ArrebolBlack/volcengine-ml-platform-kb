# 开发机与镜像

开发机用于调试环境和程序；自定义任务从镜像及明确挂载重新启动。
保存镜像不会自动把开发机挂载的 vePFS/TOS 数据变成镜像内容。
项目必须明确依赖在镜像中还是由任务挂载提供。

## 创建开发机

在机器学习平台的开发机页面创建，按当前账户选择镜像、队列、计算规格、云盘和共享存储。
需要 SSH 时配置发起连接机器的**公钥**，连接参数取当前实例详情；也可使用 WebIDE。
把需要跨实例复用的代码、环境和数据放到计划挂载的持久目录，并从第一步就明确项目子目录。

官方创建说明指出关机保留云盘内容，删除开发机会擦除其云盘；共享存储独立于开发机生命周期。
因此关机、删除和保存镜像不可互相替代。
云盘不固定为 20 GB，20 GiB 是该官方创建说明的最低容量；配额和实际配置现场查看。
来源：[创建开发机](https://www.volcengine.com/docs/6459/129233?lang=zh)，2026-09-19 查阅。

机构的网络、安装和使用限制见[机构说明](../institutions/INDEX.md)。不要把某机构的
白名单、禁止大下载或开发机回收时长写成火山所有账户的通则。

## 从开发机保存镜像

1. 项目确认要包含的解释器、系统库和入口文件；记录它们的实际版本与路径。
2. 在自己的开发机上，通过平台“保存镜像”流程填写名称和版本。镜像仓库、构建排除目录及
   大小限制以当前页面为准。共享开发机不能因本次保存而更改其他使用方的环境或登录状态。
3. 确认构建内容不包含个人凭据、登录缓存和临时实验产物。共享盘数据通过任务挂载提供，
   不将训练数据、模型缓存和整个共享盘复制进镜像。
4. 记录构建成功的实际镜像 URL；用这个版本新起短任务，验证任务内运行。通过后才用于目标实验。

不要直接复制旧资料中的镜像名称、环境路径和“已验收”描述。
2026 年 7 月某开发机的兼容测试只适用于当时镜像、驱动、库搜索路径和负载。
出现后续冲突时应回到项目资源卡和当前任务重验，不使用旧结论覆盖新事实。

上述保存流程来自原知识库的 2026 年 6—7 月实践；本轮未执行镜像构建。
官方入口：[构建自定义镜像](https://www.volcengine.com/docs/6459/72342)。

## 从 Dockerfile 构建

已有可用 Docker 构建环境时，项目维护自己的 Dockerfile 和 `.dockerignore`。
明确基础镜像、系统依赖、Python 依赖和安装方式，并保留能复现的版本说明。
在**有构建能力且能访问镜像仓库的机器 Bash**上：

```bash
: "${IMAGE_URL:?Set the writable registry/repository:version}"
docker build --tag "$IMAGE_URL" .
# 在个人终端完成该仓库要求的认证后，执行实际上传：
docker push "$IMAGE_URL"
```

当前目录是项目构建上下文，不是包含其他项目或秘密的父目录。
仓库登录和推送权限由当前机构配置决定。开发机内不一定有 Docker daemon；
需要时按平台支持方式构建，不因找不到 Docker 就安装额外后台服务。

任务 YAML 使用 `ImageUrl`。私有仓库的认证按当前平台能力配置；真实 token
不进入可提交到 Git 的 YAML。具体镜像来源见[镜像使用说明](https://www.volcengine.com/docs/undefined/106884?lang=zh)。

## 新任务内检查

| 检查 | 目的 |
|---|---|
| 解释器路径、包版本、模块 `__file__` | 确认没有导入镜像里另一份旧代码 |
| GPU 可见性与真实 kernel | 确认驱动、用户态 CUDA 与框架实际兼容 |
| 数据与输出挂载 | 确认路径、权限、读写与持久化 |
| 最小项目步骤 | 确认不是只有 import 成功 |
| 多卡/多机通信（用到时） | 确认所需范围的通信正确 |

不要仅凭 `nvidia-smi`、设备可见或库 import 成功宣布 CUDA 可用。
也不要将 `/usr/local/cuda/compat` 自动加到所有任务的库搜索路径；应依据实际框架与驱动组合诊断。
只调整项目自己的环境，并记录有效配置。

如果更换开发机镜像，先确认根盘所需数据已有持久副本；官方说明该操作会清除根目录数据。
来源：[更换开发机镜像](https://www.volcengine.com/docs/6459/1526760)，2026-09-19 查阅。
